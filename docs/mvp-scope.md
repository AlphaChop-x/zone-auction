# Объём первой итерации Zone Auction

Дата: 21 октября 2026. Основание: согласования подготовки лабораторной №6 и
прямое разрешение пользователя реализовать только запускаемую основу с заделом
на последующее получение данных с сервера.

## Текущая задача: запускаемая основа

- Тот же репозиторий, frontend на React/TypeScript/Vite/React Router,
  минимальный backend на ASP.NET Core 10 без дополнительных слоёв и библиотек.
- Главная на основе существующей вёрстки: светлая тема, Manrope, красный акцент,
  локальные стили и иллюстрации. Исходники предыдущих лабораторных сохраняются.
- Начальное состояние без фиктивной выдачи, цен, количества лотов и популярности.
  Поиск/категории отключены до подключения справочника.
- Главная, маршруты будущих лотов и подробностей с честными заглушками,
  экран неизвестного маршрута.
- `GET /api/health` → `200 {"status":"ok"}`; frontend действительно запрашивает
  его через `/api`. Ошибка имеет ручной повтор, ожидание ограничено 8 секундами.
- Vite proxy `/api` на backend; публичные серверные настройки внешнего API,
  безопасный пример локальной конфигурации и исключение локального секрета из Git.
- README, lock-файл, журнал, сборки и проверка совместного запуска.

Health подтверждает работу собственного сервера. Он не подтверждает доступ к
аукциону, авторизацию приложения или актуальность данных. Секрет для этой задачи
не нужен, внешние запросы не выполняются.

## Решения для первой итерации относительно полного ТЗ

1. Аккаунты, регистрация/вход, избранное и синхронизация отложены.
2. PostgreSQL, EF Core, Identity, Docker и production-размещение отложены.
3. Используется только светлое оформление; тёмная тема из frontend-бэклога
   не входит в согласованный объём.
4. Регион фиксирован RU. В обновляемом интерфейсе используется название
   STALZONE согласно актуальной документации. Название проекта — Zone Auction.
5. Неподтверждённые рыночные показатели из макета не используются как данные.
6. Минимальный .NET backend входит в объём ради безопасной реальной интеграции.
   Полный Definition of Done исходного ТЗ этой основой не достигается.

## Задел и следующие задачи (сейчас не реализованы)

Основной сценарий лабораторной: поиск реального предмета → выбор → лоты →
фильтры/сортировка → подробности. Данные должен возвращать собственный backend,
а не встроенный демо-адаптер и не прямой запрос браузера с секретом.

- RU-справочник из официального `EXBO-Studio/stalzone-database` с фиксированной
  ревизией; серверный поиск `GET /api/items` без массового опроса аукциона.
- Проверка production OAuth `client_credentials` и реальных лотов RU;
  `GET /api/items/{id}/lots`, первая страница, дозагрузка, ручное обновление.
- Серверный токен в памяти, тайм-ауты, кэш, объединение одинаковых запросов,
  общий ограничитель, корректная обработка 429 и `Retry-After`.
- Фильтры/сортировка по загруженному набору, цена единицы, источник и время
  получения; состояния загрузки, пустой выдачи и ошибок.
- Денежные значения предполагается передавать десятичными строками, без
  потери точности внешнего int64.
- Внешняя схема не содержит стабильного ID лота: предполагаются временные ID
  строк и подробности из загруженного набора, без обещания точной межстраничной
  дедупликации. Повтор принятой страницы не должен добавляться повторно.
- Предварительное согласованное допущение `buyoutPrice: 0 → null` требует
  подтверждения живыми данными; пока никакого преобразования нет.

`ApiBaseUrl` подготовлен как настраиваемый production-адрес из документации.
Его работоспособность с реквизитами и доступность аукциона в этой задаче
не проверялись. Страницы лотов сейчас не делают запросов и не имеют фиктивных DTO.

## Приёмка основы

Сборка backend, прямой и проксированный health, TypeScript и production-сборка,
совместный запуск, загрузка локальных ресурсов, компоновка 360/768/1440 px,
отсутствие секретов в изменениях и клиентской сборке. Фактические результаты,
ограничения и ручной чек-лист ведутся в `ai-work-log.md`.
