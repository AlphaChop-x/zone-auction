# Объём первой итерации Zone Auction

Дата: 21 октября 2026. Основание: согласования подготовки лабораторной №6 и
прямое разрешение пользователя реализовать только запускаемую основу с заделом
на последующее получение данных с сервера.

## Завершённая задача: запускаемая основа (2026-10-21)

- Тот же репозиторий, frontend на React/TypeScript/Vite/React Router,
  минимальный backend на ASP.NET Core 10 без дополнительных слоёв и библиотек.
- Главная на основе существующей вёрстки: светлая тема, Manrope, красный акцент,
  локальные стили и иллюстрации. Исходники предыдущих лабораторных сохраняются.
- Начальное состояние без фиктивной выдачи, цен, количества лотов и популярности.
  Поиск/категории отключены до подключения справочника.
- Главная, маршруты будущих лотов и подробностей с честными заглушками,
  экран неизвестного маршрута.
- `GET /api/health` → `200 {"status":"ok"}`; frontend действительно запрашивает
  его через `/api`. Ошибка имеет ручной повтор, ожидание ограничено 8 секундами.
- Vite proxy `/api` на backend; публичные серверные настройки внешнего API,
  безопасный пример локальной конфигурации и исключение локального секрета из Git.
- README, lock-файл, журнал, сборки и проверка совместного запуска.

Health подтверждает работу собственного сервера. Он не подтверждает доступ к
аукциону, авторизацию приложения или актуальность данных. Секрет для этой задачи
не нужен, внешние запросы не выполняются.

## Решения для первой итерации относительно полного ТЗ

1. Аккаунты, регистрация/вход, избранное и синхронизация отложены.
2. PostgreSQL, EF Core, Identity, Docker и production-размещение отложены.
3. Используется только светлое оформление; тёмная тема из frontend-бэклога
   не входит в согласованный объём.
4. Регион фиксирован RU. В обновляемом интерфейсе используется название
   STALZONE согласно актуальной документации. Название проекта — Zone Auction.
5. Неподтверждённые рыночные показатели из макета не используются как данные.
6. Минимальный .NET backend входит в объём ради безопасной реальной интеграции.
   Полный Definition of Done исходного ТЗ этой основой не достигается.

## Справочник и поиск (2026-10-24, реализовано)

- Локальный индекс 2364 реальных предметов официального RU-справочника,
  ревизия `33e2c75254c6fdb41221d7ca5310f9838b74d244`, воспроизводимый импорт.
- `GET /api/items` по контракту подготовки: название без учёта регистра,
  обрезка пробелов, определённый порядок, валидация и пагинация.
- `GET /api/items/{id}` для прямой ссылки и перезагрузки страницы выбора;
  регистрозависимый поиск ID, отдельное состояние 404.
- Живой поиск главной, отмена устаревших запросов, начальное состояние,
  загрузка, пустая выдача и ошибка с повтором, настоящие ссылки `/items/:itemId`.
- Страница выбранного предмета: название, ID, категория, возврат и честное
  сообщение о неподключённых лотах. В URL сохраняются запрос и страница выдачи.
- Изображения официального источника с фиксированной ревизией и локальной
  заглушкой. Категории показаны как данные; неработающих фильтров нет.
- Гостевой доступ, без БД; аукционных показателей нет.

## Реальные лоты RU (2026-10-24, реализовано)

- Серверные OAuth client_credentials, токен в памяти и объединение получения,
  единственный повтор после 401; внешний API доступен только backend.
- GET /api/items/{id}/lots, строгие ID/параметры, decimal → денежные строки,
  даты UTC, временные ключи pageId + индекс. Подробности — только из текущего
  набора в памяти, без внешнего запроса по выдуманному ID лота.
- Короткий ограниченный кэш, single-flight, общий ограничитель, тайм-аут,
  безопасные ошибки и Retry-After. Фоновых запросов и постоянного хранения нет.
- На странице предмета таблица/мобильные карточки, дозагрузка, обновление,
  число загруженных строк, источник, время/диапазон, раздельные состояния и ошибки.
- Реальные production-лоты RU подтверждены, включая браузерный сценарий.
  Выявлено игнорирование limit/offset для 04yr; адаптер использует фактический
  размер страницы. Production-пагинация не объявляется подтверждённой.
- Правило отсутствия выкупа 0 → null реализовано как прежнее допущение;
  в изученных production-ответах отсутствующий выкуп не встретился.

Контракт, реальные наблюдения и настройки: `auction-integration.md`.

## Фильтрация и сортировка загруженных лотов (2026-10-24, реализовано)

- Необязательный включительный диапазон общей цены выкупа, «Только с выкупом»,
  явное применение и сброс, ошибки у полей. Некорректный диапазон не заменяет
  активные параметры. Точные BigInt-сравнения, включая дробные границы.
- Выкуп и окончание в обоих направлениях, null-выкуп всегда в конце ценовой
  сортировки; равные значения — точный временный ID строки по ordinal.
- Неизменяемый исходный набор; новые страницы и обновление обрабатываются
  текущими фильтрами. Пагинация остаётся по исходным страницам, запросов от
  фильтров нет. Активные параметры и «Показано N из M загруженных».
- Отдельное состояние нулевого результата фильтра с действием сброса;
  дозагрузка не скрывается, если источник допускает продолжение.
- Контрольный набор A/B/C — только тесты; живой сценарий проверен на RU 04yr.

Цена за штуку дополнительно реализована как точное отношение общего выкупа
и количества, с округлением только отображения и отдельным диапазоном.
Сортировка выкупа/цены за штуку/окончания переключается стрелками заголовков
или кнопками над мобильными карточками; цикл ↑ → ↓ → исходный порядок.

## Задел и следующие задачи

Основной сценарий лабораторной: поиск реального предмета → выбор → лоты →
фильтры/сортировка → подробности. Данные должен возвращать собственный backend,
а не встроенный демо-адаптер и не прямой запрос браузера с секретом.

- Подтверждение отсутствия выкупа и повторная проверка пагинации production.
- Прочие отложенные функции полного ТЗ, перечисленные выше.

## Приёмка основы

Сборка backend, прямой и проксированный health, TypeScript и production-сборка,
совместный запуск, загрузка локальных ресурсов, компоновка 360/768/1440 px,
отсутствие секретов в изменениях и клиентской сборке. Фактические результаты,
ограничения и ручной чек-лист ведутся в `ai-work-log.md`.
