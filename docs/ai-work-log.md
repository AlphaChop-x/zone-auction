## 2026-10-24 — официальный справочник и поиск предметов

### Фактическая реализация

  проверка имён файлов и ID, уникальности, официальных названий; список путей
  иконок из Git tree без скачивания всех PNG. Полная ревизия обязательна для
  аргумента импорта; по умолчанию закреплена проверенная ревизия.
- `scripts/item-name.mjs`: два фактических формата названия, `translation` →
  `lines.ru`, `text` → `text`. При отсутствии русского названия импорт прерывается.
- `backend/Data/items.ru.json`: 2364 предмета, источник
  `https://github.com/EXBO-Studio/stalzone-database`, RU, SHA
  `33e2c75254c6fdb41221d7ca5310f9838b74d244`, дата источника
  `2026-10-21T09:33:09+03:00`. В этой ревизии 2364 переведённых названия,
  обычных текстовых названий нет. Восемь предметов без иконки (`null`).
- Backend загружает индекс один раз при старте, включает его в build/publish.
  `GET /api/items` возвращает согласованные `items`, `offset`, `limit`,
  `hasMore`, `totalCount`, `source`, `catalogRevision`. Поиск подстроки с Trim и
  OrdinalIgnoreCase; порядок по названию, затем по точному ID. Пустой запрос
  открывает весь справочник постранично.
- Проверяются длина запроса (до 200 после Trim), целые offset ≥ 0 (Int32),
  limit 1–200, повторения параметров; HTTP 400 имеет структурированное тело.
  Дополнительный собственный `GET /api/items/{id}` нужен для прямого открытия
  страницы выбора, неизвестный ID → 404. ID сохраняются и сравниваются Ordinal.
- Главная подключена к backend. Ввод с задержкой 250 мс, AbortController и
  флаг игнорирования устаревшего ответа, тайм-аут 8 с. Есть начальное состояние,
  загрузка, «Предметы не найдены», отдельная ошибка с ручным повтором.
- Пагинация и запрос в URL, ссылки на `/items/:itemId`, клавиатурная активация,
  браузерный возврат. Страница загружает название по ID, показывает категорию,
  ID, возврат и «Загрузка лотов ещё не подключена», отдельно обрабатывает ошибку/404.
- Категории взяты из реальных данных и показаны как подписи. Неработающие кнопки
  категорий убраны. PNG привязаны к той же ревизии, отсутствующие/недоступные
  изображения заменяются локальной иллюстрацией.
- README и scope обновлены. Внешнего поиска по названию, OAuth, лотов, цен,
  числа лотов, БД и отложенных функций в реализации нет.

- Первая попытка импорта обнаружила `_variants`: файлы `1.json` и т. п. содержат

  Все реальные ID этого снимка оказались строчными. Тест исправлен: берёт
  настоящий ID, проверяет точное сохранение и отказ при смене регистра.

## 2026-10-24 — реальные активные лоты RU

### Запрос и исходное состояние

Подключить production-лоты выбранного предмета через ASP.NET Core: OAuth,
нормализованный API, кэш/ограничитель/single-flight, таблица и мобильные карточки,
дозагрузка, обновление, состояния и проверки, документация и локальный коммит.
Фильтры и пользовательская сортировка не входят в задачу.

Исходный HEAD `a5617a4`. Отслеживаемое дерево чистое; прежние пользовательские
`MVP_PREPARATION.md` и два DOCX сохранены вне задачи. Прочитаны код поиска,
конфигурация, журнал/scope и §4/§7 подготовки, повторно получен официальный
OpenAPI. Подготовка не подтверждала авторизованные лоты, поэтому живая
проверка выполнена отдельно в этой задаче.

Переданные пользователем реквизиты сохранены только в игнорируемом
`backend/appsettings.Local.json`, без включения в документацию/коммит.
Настройки окружения сервера имеют приоритет. Файл также исключён из
копирования в build/publish.

### Реализация

- `AuctionTransport`: общий HttpClient, сериализация и интервал всех исходящих
  запросов, включая OAuth, тайм-аут 15 с с конфигурацией, Retry-After и
  обработка наблюдаемых remaining/reset. Сырые диагностические тела не передаются.
- `AuctionTokenProvider`: client_credentials с пустым scope, раннее обновление
  токена в памяти, объединённая авторизация, краткое запоминание ошибки.
  `AuctionClient` допускает один повтор авторизации только после 401; 403 и
  повторный 401 не создают бесконечного цикла.
- `AuctionNormalizer`: реальные поля → собственный DTO; цены decimal → строки
  без потери Int64, даты UTC; отсутствующий currentPrice → null. Количество
  положительное, ID не меняет регистр. Допущение buyoutPrice=0 → null сохранено.
- `AuctionPages`: общий ограниченный кэш, объединение одинаковых запросов,
  предел очереди. Отмена браузера не отменяет общий запрос другим посетителям.
  Кэш сохраняет исходные fetchedAt/pageId/ключи. Фоновых опросов/очистителей нет.
- `GET /api/items/{id}/lots`: проверка ID в справочнике и пагинации, 404 отдельно
  от 200 с пустыми лотами, безопасные 429/502/503/504 с code/message. Известный
  Retry-After не перезапускается на кэшированных ошибках.
- `LotsPanel`: первая страница, кнопки «Загрузить ещё»/«Обновить», отдельный
  индикатор дозагрузки, синхронный запрет повторных кликов, отмена и игнорирование
  старых ответов, новый набор при смене предмета. Offset берётся из nextOffset
  сервера, рассчитанного по длине исходной страницы. Одна страница не добавляется
  дважды; одинаковые по полям строки разных страниц не склеиваются.
- Постоянно видны число загруженных лотов, «По загруженным лотам», источник и
