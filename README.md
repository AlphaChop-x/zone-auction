# Zone Auction

## Быстрый старт — Docker

Нужны **Docker с поддержкой Linux-контейнеров и Docker Compose v2 или новее**.
Локальные Node.js и .NET SDK не требуются. Команды выполняются из корня репозитория.

1. Создайте файл окружения:

   ```sh
   cp .env.example .env
   ```

   В PowerShell: `Copy-Item .env.example .env`. Если `.env` уже существует,
   используйте его, сохранив свои настройки.

2. Для загрузки реальных лотов заполните в `.env` поля
   `Stalcraft__ClientId` и `Stalcraft__ClientSecret`.
   Без реквизитов доступны поиск предметов и проверка состояния сервера.

3. Запустите приложение:

   ```sh
   docker compose up --build -d
   ```

**Открыть приложение: <http://localhost:8080>**

Для другого порта задайте `FRONTEND_PORT` в `.env`.

```sh
# Проверить конфигурацию
docker compose config --quiet

# Посмотреть состояние контейнеров
docker compose ps

# Посмотреть журналы
docker compose logs --tail=100 frontend backend
docker compose logs -f

# Остановить приложение и удалить контейнеры/сеть
docker compose down

# Пересобрать и запустить после изменения исходников или .env
docker compose up --build -d
```

### Запуск на сервере без скачивания репозитория вручную

Передайте на сервер только [`compose.remote.yaml`](compose.remote.yaml),
сохраните его там как `compose.yaml` и создайте рядом `.env` с полями
`Stalcraft__ClientId` и `Stalcraft__ClientSecret` (пример — в `.env.example`).
Затем выполните из этой папки:

```sh
docker compose config --quiet
docker compose up --build -d
```

Docker BuildKit сам скачает исходники из GitHub и соберёт оба образа на сервере.
Локальная копия репозитория, Git, Node.js и .NET SDK на сервере не требуются.
Нужен доступ к GitHub, реестрам образов и источникам зависимостей во время сборки.

По умолчанию собирается ветка `main`. Для фиксированной версии можно задать
`ZONE_AUCTION_REF` в `.env`: полный SHA коммита или тег. Для обновления из `main`
повторите `docker compose up --build -d`.
Приложение доступно по адресу `http://IP-СЕРВЕРА:8080`, если порт разрешён
на сервере. Для HTTPS используется внешний reverse proxy с сертификатом.

При проверке этого варианта из репозитория используйте явный файл:
`docker compose -f compose.remote.yaml up --build -d`.

## О проекте

Zone Auction — неофициальное приложение для поиска предметов и просмотра
активных лотов аукциона **STALZONE** в регионе **RU**.

- Поиск по официальному справочнику из 2364 предметов с изображениями и категориями.
- Реальные активные лоты: количество, начальная цена, выкуп, текущая ставка
  при наличии и время окончания в UTC.
- Фильтры общей цены выкупа и цены за единицу, переключатель «Только с выкупом».
- Сортировка по выкупу, цене за единицу и времени окончания.
- Подробности выбранного лота, ручное обновление и загрузка следующих страниц.
- Сохранение поиска в URL, возврат к списку с сохранением фильтров и сортировки.
- Адаптивный интерфейс: таблица на широком экране и карточки на мобильном.

Например, поиск `штрих` находит Костюм «Штрих» и открывает `/items/3g6p5`.
Наличие предмета в справочнике не гарантирует наличия предложений на аукционе.

## Стек и архитектура

**Frontend:** React 19, TypeScript, Vite 7, React Router 7.
**Backend:** ASP.NET Core 10, серверная OAuth-интеграция с официальным API.

Браузер обращается к относительному `/api`. Backend получает внешний OAuth-токен,
хранит его в памяти и возвращает клиенту только нормализованные данные.
Реквизиты и токен внешнего API не передаются браузеру.

В Docker frontend собирается через `npm ci` по lock-файлу и раздаётся nginx.
Backend собирается через `dotnet publish` и работает под пользователем `app`
в ASP.NET runtime. Наружу опубликован только frontend; backend доступен
по HTTP внутри сети Compose. Запросы к внешним OAuth/API выполняются по HTTPS.

nginx проксирует `/api` без изменения пути и параметров, сохраняя статусы,
JSON-ответы и `Retry-After`. Вложенные маршруты React поддерживают прямое
открытие и обновление страницы через fallback на `index.html`.

Frontend запускается после готовности backend. Проверка
<http://localhost:8080/api/health> возвращает `{"status":"ok"}` и обращается
только к собственному серверу, без запросов к STALZONE.

Аккаунты и база данных не используются. Обновление лотов выполняется вручную;
backend использует кратковременный кэш и объединяет одинаковые запросы.

## Конфигурация

### Docker Compose

Настройки задаются в корневом `.env`. Доступные параметры перечислены
в [`.env.example`](.env.example).

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `FRONTEND_PORT` | Внешний порт приложения | `8080` |
| `Stalcraft__ClientId` | ID приложения для внешнего API | Пусто |
| `Stalcraft__ClientSecret` | Секрет приложения для внешнего API | Пусто |
| `Stalcraft__ApiBaseUrl` | Адрес API аукциона | `https://eapi.stalzone.com/` |
| `Stalcraft__TokenUrl` | Адрес OAuth | `https://exbo.net/oauth/token` |
| `Stalcraft__Region` | Регион аукциона | `RU` |

Дополнительные параметры секции `Stalcraft` управляют тайм-аутами,
ограничением частоты запросов и кэшем. В окружении используется разделитель `__`,
например `Stalcraft__RequestTimeoutSeconds`.

Compose передаёт серверные настройки только окружению backend при запуске.
`.env` исключён из Git и build context. Локальный
`backend/appsettings.Local.json` в Docker не используется и в образ не попадает.
Не помещайте реквизиты в `VITE_*` или отслеживаемые файлы.
Для проверки конфигурации используйте `docker compose config --quiet`,
чтобы не выводить подставленные значения.

При пустых реквизитах запрос лотов возвращает `503 source_not_configured`;
поиск по справочнику продолжает работать.

### Локальная разработка

Публичные настройки находятся в `backend/appsettings.json`.
Для загрузки лотов скопируйте `backend/appsettings.Local.example.json`
в `backend/appsettings.Local.json` и заполните ID и секрет.
Этот файл исключён из Git и build/publish.

Также можно задать `Stalcraft__ClientId` и `Stalcraft__ClientSecret`
в окружении процесса backend. Переменные окружения имеют приоритет
над локальным JSON. После изменения настроек перезапустите backend.
Корневой `.env` автоматически читает Compose, а не `dotnet run`.

## Разработка без Docker

Нужны **Node.js 24 с npm** и **.NET SDK 10**.

Из корня репозитория запустите backend:

```sh
dotnet run --project backend/ZoneAuction.Api.csproj
```

В другом терминале запустите frontend:

```sh
cd frontend
npm ci
npm run dev
```

Приложение: <http://127.0.0.1:5173/>.
Backend: <http://localhost:5080/api/health>.
Vite проксирует `/api` на backend. Остановка — `Ctrl+C` в каждом терминале.

## Сборка и тесты

Из корня репозитория:

```sh
dotnet build backend/ZoneAuction.Api.csproj
node --test scripts/search.test.mjs scripts/lots.test.mjs scripts/lot-filters.test.mjs

cd frontend
npm ci
npm run typecheck
npm run build
npx playwright install chromium
npm run test:ui
```

Серверные тесты проверяют поиск, формат данных, пагинацию, OAuth,
кэширование, ограничение запросов и обработку ошибок. Для них нужны свободные
порты `127.0.0.1:5088` и `:5089`. Тесты фильтров проверяют точные денежные
вычисления, диапазоны и сортировку.

UI-тесты запускают Chromium и Vite на `127.0.0.1:5181`, проверяя подробности,
навигацию, фильтры, состояния ошибок, клавиатуру и адаптивную компоновку.
Тесты используют управляемые ответы и не требуют настоящих реквизитов API.

## API

| Метод и путь | Описание |
| --- | --- |
| `GET /api/health` | Состояние собственного backend |
| `GET /api/items?query=штрих&offset=0&limit=20` | Поиск и пагинация справочника |
| `GET /api/items/{id}` | Предмет по точному ID |
| `GET /api/items/{id}/lots?offset=0&limit=20` | Активные лоты выбранного предмета |

Поиск выполняется по подстроке названия без учёта регистра.
ID предметов регистрозависимы. `offset` — неотрицательное целое,
`limit` — от 1 до 200, по умолчанию 20. Неверные параметры возвращают
400, неизвестный предмет — 404. Ошибки внешнего API не подменяются пустой выдачей.

Денежные значения передаются десятичными строками и обрабатываются на клиенте
через `BigInt`. Цена за единицу рассчитывается из общего выкупа и количества;
округление применяется только при отображении.

Подробный контракт, серверные политики и особенности источника:
[`docs/auction-integration.md`](docs/auction-integration.md).

## Особенности работы с лотами

- Фильтры и сортировка применяются только к загруженным страницам и не вызывают
  дополнительные запросы к API. Оба диапазона цены работают одновременно.
- «Загрузить ещё» добавляет страницу, «Обновить» заменяет набор после успешного
  ответа. При ошибке обновления прежние данные остаются с сообщением об ошибке.
- Время получения и источник отображаются рядом со списком. Предложения могут
  измениться или исчезнуть после загрузки.
- Подробности `/items/:itemId/lots/:lotId` доступны из текущего набора в памяти
  браузера. После перезагрузки страницы временный ID не восстанавливает лот;
  приложение предлагает вернуться к списку.
- Внешний API может игнорировать параметры пагинации. Продолжение рассчитывается
  по фактическому размеру ответа; точность внешней пагинации не гарантируется.
- Значение выкупа `0` интерпретируется как отсутствие выкупа.

## Справочник предметов

Источник: [EXBO-Studio/stalzone-database](https://github.com/EXBO-Studio/stalzone-database),
регион `ru`. Индекс хранится в `backend/Data/items.ru.json` вместе с метаданными
источника и ревизией. Он входит в сборку backend; повторный импорт для запуска
не требуется. Изображения загружаются из той же ревизии официального репозитория;
при отсутствии изображения отображается локальная заглушка.

Для обновления индекса нужны Node.js и Git:

```sh
node scripts/import-items.mjs
# Импорт конкретной ревизии:
node scripts/import-items.mjs <commit-sha>
```

После импорта пересоберите контейнеры или перезапустите локальный backend.
