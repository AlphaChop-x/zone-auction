# Zone Auction

Неофициальный мониторинг аукциона **STALZONE**, регион **RU**,
для лабораторной №6. React + TypeScript + Vite + React Router и минимальный
ASP.NET Core 10 backend. Светлое оформление, красный акцент и локальный Manrope
сохранены из предыдущих лабораторных.

**Подключён поиск по официальному справочнику: 2364 предмета.** Начните с названия
или его части, например `штрих`: результат «Костюм «Штрих»» открывает
`/items/3g6p5`. На странице предмета загружаются **реальные активные лоты RU**:
количество, начальная цена, выкуп и окончание (UTC), ручное обновление и дозагрузка.
Поиск доступен гостю без реквизитов; для лотов нужны серверные реквизиты API.
Аккаунтов, БД и автоматического опроса нет.
`/api/health` проверяет только наш backend.

## Требования и запуск

- .NET SDK 10 (проверено на 10.0.302).
- Node.js 24 LTS с npm (проверено на Node 24.20.0, npm 11.13.0).
- Git — только для повторного импорта справочника.

Команды выполняются из корня этого репозитория. Первый терминал:

```sh
dotnet run --project backend/ZoneAuction.Api.csproj
```

Backend: <http://localhost:5080/api/health>, ожидается `{"status":"ok"}`.

Второй терминал:

```sh
cd frontend
npm ci
npm run dev
```

Главная: <http://127.0.0.1:5173/>. Оба процесса должны работать одновременно.
Vite слушает локальный IPv4 и проксирует `/api` на `http://localhost:5080`.
Браузер обращается к своему origin; реквизиты внешнего API ему не нужны.
Остановка каждого процесса — `Ctrl+C` в соответствующем терминале.

## Серверные настройки

Для справочника реквизиты не требуются. Для загрузки лотов:

1. Скопируйте `backend/appsettings.Local.example.json` в
   `backend/appsettings.Local.json`.
2. Впишите ID и секрет только в локальный файл. Он исключён из Git.
3. Либо задайте переменные окружения в терминале backend (PowerShell):

```powershell
$env:Stalcraft__ClientId = '<ваш ID>'
$env:Stalcraft__ClientSecret = '<ваш локальный секрет>'
dotnet run --project backend/ZoneAuction.Api.csproj
```

Это placeholders, не настоящие реквизиты. Переменные окружения имеют приоритет
над локальным JSON. После изменения настроек перезапустите backend.
Не помещайте реквизиты во frontend, `VITE_*`, README или отслеживаемые файлы.

Публичные настройки находятся в `backend/appsettings.json`: регион RU,
`https://eapi.stalzone.com/`, OAuth `https://exbo.net/oauth/token`, тайм-аут 15 с.
Ключ секции `Stalcraft` сохранён для согласованных имён переменных окружения.
Backend выполняет OAuth `client_credentials`, хранит токен в памяти, получает
лоты и возвращает только нормализованные DTO. Локальный JSON исключён также
из копирования в build/publish. Подробный контракт и результаты живой проверки:
[`docs/auction-integration.md`](docs/auction-integration.md).

Настройки секции `Stalcraft`: `RequestTimeoutSeconds=15`,
`MinimumRequestIntervalMs=1000`, `CacheSeconds=10`, `ErrorCacheSeconds=2`,
`MaxCachedPages=256`, `MaxPendingPages=16`. Это политики приложения, а не
опубликованные лимиты EXBO. Один общий ограничитель обслуживает OAuth и лоты,
учитывает `Retry-After` и наблюдаемые заголовки исчерпания лимита. Одинаковые
одновременные запросы объединяются; фоновых запросов нет.

## Проверки и сборка

```sh
dotnet build backend/ZoneAuction.Api.csproj
node --test scripts/search.test.mjs scripts/lots.test.mjs
cd frontend
npm run typecheck
npm run build
```

16 тестов используют встроенный Node test runner: 5 тестов поиска и 11 тестов
адаптера лотов. Нужны свободные `127.0.0.1:5088` и `:5089`.
Тесты лотов запускают контролируемый локальный HTTP-источник на свободном порту
и подставляют тестовые серверные настройки; production и настоящие реквизиты
они не используют. Проверяются точные Int64-цены, UTC, пагинация, объединение
запросов, кэш, ограничитель, OAuth/401, истечение токена, 429 и тайм-аут.
**Это тесты с подменённым источником, не проверка живого API.**

Для просмотра собранного frontend из `frontend/`:

```sh
npm run preview -- --host 127.0.0.1
```

`preview` проверяет статическую сборку, это не production-размещение и не
полноценный совместный запуск: `/api` proxy настроен для `npm run dev`.

## Официальный справочник и повторный импорт

Источник: <https://github.com/EXBO-Studio/stalzone-database>, регион `ru`.
Ревизия: `33e2c75254c6fdb41221d7ca5310f9838b74d244` (обновление 2026-10-21).
Импорт выполнен 2026-10-24. Точная дата исходного коммита хранится в `sourceDate`
в `backend/Data/items.ru.json`, рядом с `source`, `catalogRevision` и `region`.
Индекс отслеживается Git и включается в сборку/publish backend; для обычного
запуска сеть и повторный импорт не нужны. Backend читает индекс один раз при старте.

Из корня репозитория:

```sh
node scripts/import-items.mjs
# Или явно укажите полный SHA нужной ревизии:
node scripts/import-items.mjs 33e2c75254c6fdb41221d7ca5310f9838b74d244
```

Импорт получает JSON `ru/items` через sparse checkout, проверяет совпадение ID
из JSON и имени файла, уникальность ID и наличие названия. Модификации
`_variants` имеют тот же ID и не становятся отдельными предметами. Русский текст
читается из `name.lines.ru` для `translation`, из `name.text` для `text`; английский
fallback не подставляется. В текущем снимке 2364 `translation`, 0 `text`.
Регистр ID сохраняется на всех этапах. Категория — реальный путь `category`
источника (например `armor/clothes`). Категории показаны как подписи, фильтров нет.

Список путей Git позволяет проверить наличие PNG без загрузки всех изображений.
`iconUrl` привязан к той же ревизии на raw.githubusercontent.com; у восьми предметов
он `null`. Браузер загружает изображения по мере необходимости; при отсутствии
или сетевой ошибке показывает локальную заглушку. Два импорта одной ревизии
дали побайтово одинаковый индекс. После обновления индекса перезапустите backend.

## API и поведение поиска

`GET /api/items?query=штрих&offset=0&limit=20` возвращает:

```json
{
  "items": [{ "id": "3g6p5", "name": "Костюм «Штрих»", "category": "armor/clothes", "iconUrl": "https://raw.githubusercontent.com/EXBO-Studio/stalzone-database/33e2c75254c6fdb41221d7ca5310f9838b74d244/ru/icons/armor/clothes/3g6p5.png" }],
  "offset": 0,
  "limit": 20,
  "hasMore": false,
  "totalCount": 1,
  "source": "https://github.com/EXBO-Studio/stalzone-database",
  "catalogRevision": "33e2c75254c6fdb41221d7ca5310f9838b74d244"
}
```

- Поиск подстроки: `Trim` + `OrdinalIgnoreCase`; ID не нормализуются.
- Порядок: название `OrdinalIgnoreCase`, затем ID `Ordinal` для равных названий.
- Пустой/отсутствующий `query` возвращает страницу всего справочника.
- По умолчанию `offset=0`, `limit=20`; допустимы целые `offset` от 0 до
  2147483647, `limit` от 1 до 200, запрос до 200 символов после обрезки пробелов.
  Повторение параметров отклоняется. Неверные значения → HTTP 400 с
  `{code, message, fieldErrors}`; пустой результат → HTTP 200 с `items: []`.
- `GET /api/items/{id}` возвращает один предмет; неизвестный ID или другой
  регистр → HTTP 404 с `{code, message}`. Это собственный маршрут для прямых ссылок.
- На главной есть начальное состояние, загрузка, пустая выдача и отдельная ошибка
  с повтором. Ввод отложен на 250 мс, запрос ограничен 8 секундами; предыдущий
  запрос отменяется, его запоздалый ответ игнорируется. Запрос/страница хранятся
  в URL, браузерный возврат восстанавливает поиск.
- Результаты — ссылки на `/items/:itemId`, работают с Tab/Enter и в новой вкладке.
  Страница получает название по ID и активные лоты через backend, поддерживает
  перезагрузку и возврат. Справочник не гарантирует наличие на аукционе.

## Лоты выбранного предмета

- `GET /api/items/{id}/lots?offset=0&limit=20`: ID проверяется по справочнику
  с учётом регистра, limit 1–200, offset — неотрицательный Int32.
- Неизвестный предмет → 404; известный без предложений → 200 с пустым `items`.
  Ошибка источника/429 не подменяется пустым списком; доступен ручной повтор.
- Денежные значения — **десятичные строки**, на backend используется `decimal`,
  в браузере для отображения `BigInt`, без преобразования в `Number`.
- `Загрузить ещё` добавляет страницу, `Обновить` заменяет набор первой страницей.
  Обновление может прочитать краткий кэш и сохраняет исходный `fetchedAt`.
  При ошибке обновления прежний набор и время остаются с явным сообщением.
- Постоянно видны загруженное количество, «По загруженным лотам», источник и
  время/диапазон получения. На ширинах менее 768 px таблица становится карточками.
- `/items/:itemId/lots` открывает тот же список. `/items/:itemId/lots/:lotId`
  показывает только запись из текущего набора в памяти браузера. После потери
  набора/перезагрузки временный ID не восстанавливает лот из внешнего API.

Живой production-сценарий RU подтверждён в Chromium для `3g6p5` (1 лот на момент
проверки); `0r2qk` вернул «Лотов нет». Данные аукциона меняются.
**Выявлены ограничения источника:** для `04yr` он вернул все 55 строк вопреки
`limit=20`; `offset=20` вернул тот же массив. Продолжение рассчитывается по
фактической длине исходной страницы, строки локально не обрезаются.
Работа дозагрузки проверена на управляемом HTTP-источнике; корректность
production-пагинации этими тестами не подтверждается.

Правило `buyoutPrice: 0 → null` реализовано как ранее согласованное допущение.
В просмотренных живых ответах выкуп был положительным, поэтому отсутствие
выкупа пока подтверждено только контрольным тестом, не production-наблюдением.

Неизвестный маршрут показывает 404-экран.
Подробности выполнения и ручной чек-лист — в `docs/ai-work-log.md`.
